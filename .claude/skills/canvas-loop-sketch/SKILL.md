# canvas-loop-sketch

canvas-loop (`@ianbicking/canvas-loop`) is a deterministic, browser-less, frame-stepped Canvas2D sandbox for agent programming: you write a p5-style or TEA sketch, run one CLI command, and `Read` back a single frame-tagged **transcript** with rendered PNGs inline. Reach for it whenever you need to *see* what a program draws — sims, data-viz, generative/creative-coding figures, interactive canvas toys — without driving a live browser. It is not for real DOM/CSS app UI; that stays the `browse` skill.

Read these before writing — they are the reference; do not re-derive or inline them:

- `canvas-loop/README.md` — the mutable tier (`setup`/`draw`), the full `Sketch` drawing API, events file, capture policy, and the `./react` `<SketchFigure>` embed component.
- `canvas-loop/TEA.md` — the **TEA tier** (pure `init`/`update`/`draw` fold, declared `params`, the `Msg` union, the enforced discipline + lint). **Prefer this tier for new work**; name the file `*-tea.ts` so the lint discipline applies.
- `canvas-loop/gallery/README.md` — the exercise-corpus schema and the add / re-exercise flow.

## The loop

1. Write a sketch `.ts` (a TEA `*-tea.ts` unless you have a reason not to).
2. Run it:
   ```sh
   pnpm --dir canvas-loop run cli run <sketch.ts> --events <events.json> --out out [--seed 42] [--frames 120]
   ```
3. `Read out/transcript.md` — the inline `![frame N](frame-NNNN.png)` images render directly in `Read`.
4. Inspect the frames, fix, re-run. A cycle is ~5s; determinism means a re-run reproduces the exact pixels.

## Events are tests

One events JSON is simultaneously a test, a reproduction, and a demo. Scripted `{frame, type, …}` entries (`mousedown`/`mousemove`/`mouseup`/`keydown`/`keyup`, plus TEA `param`/`trigger`) dispatch through the same handler / `Msg` path as real input. **Guarantee:** every event for frame N fires, in file order, *before* frame N's `draw` — so hit-testing a moving target is a pure calculation off the sketch's own position formula, never trial-and-error. To pin a frame the capture policy would otherwise skip, without perturbing state, script a snapshot: `{ "frame": 40, "type": "snapshot", "label": "peak" }` (the scriptable twin of `snapshot(label?)`).

## Determinism levers

Time is a fixed timestep, RNG is seeded (`--seed`), and `Math.random`/`Date.now`/`performance.now` are disabled inside a sketch — two runs are byte-identical. Exploit that:

- Derive exact click coordinates from the sketch's own math instead of guessing.
- Add a `timeScale`-style param to land frames on round instants (e.g. drive a clock to exactly 11:15:00) so you can spot-check against unambiguous positions.
- Add a `showDigital`/readout param as a self-verification lever — compare the pixels against the number the model believes.

Whenever the visual has a closed form, "visually difficult" collapses to "calculable + spot-checkable at chosen frames". Only genuinely aesthetic/organic targets (a tree that reads as a tree, hand-tuned easing) actually need many iteration cycles.

## Gallery

To bank an exercise (task + delivered sketch + events + metadata) or re-run an old one, follow `canvas-loop/gallery/README.md`: create `gallery/<slug>/` with `task.md`, `sketch*.ts`, `events.json`, and `meta.yaml`; append one `runs.jsonl` line (`action: authored | rerun | ported`); then `pnpm --dir canvas-loop run gallery:check` (twice-render determinism + lint) must pass before committing. No PNGs or transcripts are committed — output is reproducible from (sketch, events, seed, harness-commit).

## Audit norms

From the experiment record (`issues/exploration/2026-07-13-canvas-tight-loop-agent-programming.md`):

- **Verify by frames, not logs.** Logs say what the code *believes*; the frames say whether rendering *agrees*. Render-only bugs — a stale HUD label after deselect, text ghosting under trails, a phantom shape — are invisible in logs and only caught in the PNGs. The interleaved transcript is what makes a log↔pixel mismatch trivial to spot.
- **Stranger-test honesty.** A final-frame self-grade drifts from the actual pixels (agents have claimed elements that aren't visible in the frame). State only what a stranger would see in the image, and call for independent eyes on aesthetic results.
