## How this was measured

- **Use:** each package's imports, `require`/`createRequire().resolve` calls, `package.json` scripts, tool configs, and shell scripts were read. A package name alone was never taken as evidence.
- **knip:** `knip --include dependencies,unlisted,binaries,unresolved` reports no unused dependencies. It reports only two unlisted system binaries (`getent`, `restic`). knip covers only root, `beebox`, and `beebox/src/frontend`; `knip.ts` `ignoreWorkspaces` skips the other ten packages. Its `ignoreDependencies` list also hides two dead packages (see below). The `knip-sweep` schedule has no dependency findings pending.
- **Weight:** the installed size of the package plus its unique transitive closure, walked through `node_modules` with Node's lookup rules. "Only it pulls" counts the transitive packages that no other direct dependency in the repo reaches, so it is what removal actually frees. Platform binaries are counted for darwin-arm64 only.
- **Where it lands:** deploy runs a full `pnpm install` (dev deps included, because the runtime uses `tsx`) of root, `beebox`, `beebox/src/frontend`, `personal-vibe-check`, and `tap-check`. On the production server, devDependencies of those five packages cost the same as runtime ones. The other workspaces never reach the server.

## Top candidates, ordered by payoff

1. **Three copies of the Claude agent SDK, about 280 MB each.** Root pins `0.3.226`, `workstreams-app` pins `0.3.227`, and `beebox` pins `0.3.310`. Each install has its own platform binary. `bin/update-agent-sdk.ts` bumps only beebox's pin. Root code never imports the SDK, but the root copy is installed on the server. The beebox runtime resolves the correct nested copy (`beebox/src/core/sdk-binary-path.ts`). `bundledClaudeVersion()` in the update script reads the hoisted root copy, so it reports `2.1.226` while beebox runs `2.1.310`. Proposed: **remove** the root pin and repoint `bundledClaudeVersion()`. Then either have `workstreams-app` follow beebox's pin, or have the update script bump both. That saves about 280 MB on the server and 280–560 MB per dev checkout. Whether the dashboard should keep the SDK for its quota read is a separate question to **file**.
2. **`madge` (79 MB, 73 packages only it pulls; on the server).** Its only job is the weekly `lint:circular` check. `oxlint`, already installed, finds the same cycles with `-D import/no-cycle --import-plugin` in 0.8 s, where madge takes 4.5 s. Proposed: **replace** with oxlint, and delete `.madgerc` and the frontend's duplicate script. Side finding: both tools report 2 live cycles, but `beebox/docs/development/maintenance.md` says "currently zero".
3. **`agent-browser` as a root devDependency (76 MB on the server).** The server never runs it. `browse/packages/agent-browser-typed` already declares it for local `bin/browse`. Proposed: **remove** the root entry and its `knip.ts` ignore, then confirm `bin/browse` still resolves the hoisted binary.
4. **`zod` in `beebox/pub-worker` is 96% of the deployed Worker's bytes.** A minified esbuild bundle is 342 KB, and 327 KB of it is zod, all for two small JWKS shapes in `beebox/pub-worker/src/access.ts`. ## Large trees kept on purpose

- `three` (37 MB) and `p5` (33 MB) are frontend runtime deps, reached only through `import()` in `FigureMount.tsx`. Each becomes its own lazy chunk, so the cost is install size, not the main bundle. `d3` stays whole because agent-written sketches get its full namespace.
- `wxt` (354 transitive packages, 53 MB only it pulls) builds `beebox-clerk`; replacing it is a large job.
- `@cloudflare/vitest-pool-workers` and `wrangler` (341 MB) run `pub-worker`'s tests against real workerd and R2 bindings. They are not on the server. Moving those tests to tap loses that fidelity.
- `tap` (303 transitive packages) runs the ~1,200 test files.
- `sharp`, `better-sqlite3`, `@googleworkspace/cli`, `@twemoji/svg`, and `markdownlint` each back a live feature (see the beebox table).

Ranges drift: `esbuild` is exact `0.25.12` in canvas-loop, `^0.25.0` in scan-uploader, and `^0.25.12` at root; `eslint` is `^9.0.0` in browse and `^9.39.2` elsewhere. `workstreams-app` gets a nested `vite` 5 and `esbuild` 0.21 because root resolves `vite` 8.
