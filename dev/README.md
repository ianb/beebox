# `dev/` — agent-built views

Things the **dev-repo agent** (Claude Code, not a box) builds for you to look at
in the browser: HTML visualizations, rendered Markdown reports, data displays.

View them via the dev router at
**`http://localhost:3210/<worktree>/dev/`** — a manifest page that lists the
built-in tools plus whatever is in this directory. Use `main` for the main
checkout or the worktree's short name for an isolated checkout.

- This directory **is tracked in git** (unlike the gitignored `scratch/`), so
  views kept here are committed and shared.
- Drop a `.html` file here and it's served as-is (inline JS/SVG/canvas work).
  Drop a `.md` file and the router renders it to HTML (via Markdoc — tables,
  code, lists all work).
- Built-in tool, not a file here: the **markdown doc browser** at
  `/<worktree>/dev/docs/` — read every `.md` in the repository, grouped by area.
- The workstream, issue, plan, and manual-testing control surfaces are router
  apps, not files in this directory: `/workstreams/`, `/workstreams/issues/`,
  `/workstreams/plans/`, and `/workstreams/testing/`.
- **`dev/tools.json`** — declare extra "Built-in tools" cards for _this_
  worktree's manifest (a full page or view that shouldn't just be a bare
  folder row). Read live from disk, so a card appears the moment you commit
  it here — no router-code change or main-merge. Shape:
  `{"tools":[{"emoji":"🔎","title":"…","href":"dev/foo/index.html","desc":"…"}]}`
  — `href` is worktree-root-relative (or a full `https://` URL); `emoji`/`desc`
  optional. (The universal doc/issue/site cards stay in router code.)
  - **Normal HTML and markdown just work** — inline JS, relative images in
    `.md` files, canvas, SVG. The bare `sandbox` CSP that used to cover `/dev/`
    (blocking scripts and, less obviously, breaking every image in rendered
    markdown) was removed 2026-08-19; the rationale lives in the decision
    comment in `workstreams-app/src/router/router-docs.ts` `serveDev`. The old `tools.json`
    `scripted` allowlist stays gone — nothing needs a grant any more.
- **Not this directory: exhibits.** Something built to ask the developer one
  question — labeled screenshots, a decision page — is an *exhibit*, not a
  `dev/` view: `bin/exhibits add` puts it in the per-workstream store (it
  survives the cull, and it carries an ask), while files here are tracked
  artifacts that merge to main. A durable exhibit-shaped app lives at
  `dev/apps/<name>/` and is served at `/apps/<name>/` on the exhibits origin.
  See `workstreams-app/docs/exhibits.md`.
- **`dev/prompts/`** — the prompt viewer (every agent prompt, the assembled
  per-situation contexts, a duplication scan, and prompt size over time).
  Generated by `pnpm prompt-viewer` in `beebox/`.
