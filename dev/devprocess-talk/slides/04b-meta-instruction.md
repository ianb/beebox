# "When you get corrected, write a rule"
## Supporting: the self-improvement instruction in three forms
- First (Mar 6): a section with examples. Compressed (May 5): one sentence. Now (Sep 12): a routing rule

```text
FIRST (bedf968cf)
When you get corrected on something — a convention you missed, a pattern you
got wrong, a tool you misused — consider whether the correction reveals a gap
in these instructions. If the mistake was caused by missing or unclear
guidance here, update this file (or the relevant doc) so the next agent
doesn't repeat it. … Keep additions concise.

NOW (d7b47dfde)
When a correction exposes missing durable guidance, put a short rule at the
narrowest accurate owner: this file for package-wide constraints, a nested
CLAUDE.md for an area, code-style.md or frontend.md for coding contracts, and
docs/ for conditional reference material.
```

Notes:
The first form is why the file grew: every correction became a rule in the always-loaded file. The current form names where a rule goes. The October retrospective adds a second counterweight: a lesson must recur before it becomes guidance.
