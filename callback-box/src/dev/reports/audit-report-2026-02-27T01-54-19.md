> Here's the flow:
> 
> **1. You write a `<message sender="agent">` in the chat thread file** (e.g., `store/chat/telegram/<slug>/thread.chat-thread.card`). The message has no `sent` or `id` attributes yet.

> 
> **6. It stamps the message with delivery proof** — adding `sent="<timestamp>"` and `id="<telegram_message_id>"` attributes back onto the XML element, then commits the updated thread file.
> 
> So the key thing: you don't create a separate outbound card. You just append the message to the thread, and the Telegram connector picks up any unsent agent messages during `cb finalize`. The `sent` attribute acts as the marker distinguishing "queued" from "delivered."
