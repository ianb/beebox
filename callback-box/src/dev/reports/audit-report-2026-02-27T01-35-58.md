## chat-thread-outbound-flow
**Prompt:** "After I write a response in a chat thread, how does it actually get sent to Telegram?"
**Expected level:** discoverable
**Watch for:** Describes the finalize/connector flow: unsent agent message found, sent via API, stamped
**Notes:** The agent shouldn't need to know the outbound mechanics to process a chat job — just write the response and commit. But understanding the flow helps debug issues. This is discoverable from connector docs.


**Agent behavior:**
- Files read: (none)
- Searches: (none)
- Response length: 223 words

**Response:**
> Here's how it works:
> 
> **The chat thread is the message queue.** When you (or an agent) write a response in a Telegram chat thread (`store/chat/telegram/<chat>/thread.chat-thread.card`), you add a `<message sender="agent">` element. At that point the message is just sitting in the file — it hasn't been sent yet.
> 
> **`cb wakeup --connector telegram` sends it.** The Telegram connector scans all chat thread files, finds agent messages that don't have a `sent` attribute, and sends them via the grammy library (`bot.api.sendMessage`). After a successful send, it stamps the message with `sent="<timestamp>"` and `id="<telegram-message-id>"`, then commits the updated thread.
> 
> So the flow is:
> 
> 1. Agent appends `<message sender="agent">response text</message>` to the thread file
> 2. `cb wakeup --connector telegram` runs (either manually or triggered by a schedule/webhook)
> 3. The connector finds that unsent message (no `sent` attribute)
> 4. Calls the Telegram Bot API to deliver it
> 5. Stamps it with `sent` and `id` so it won't be sent again
> 
> **For real-time delivery**, there's also a webhook route (`/api/telegram/webhook`) — when Telegram pushes an incoming message, the webapp processes it and can trigger a wakeup cycle, so replies go out promptly rather than waiting for the next scheduled tick.
> 
> This is different from Pushover notifications, which use `box/output/` cards and `cb finalize`. Telegram is bidirectional and uses the persistent chat thread as both conversation history and outbound queue.
