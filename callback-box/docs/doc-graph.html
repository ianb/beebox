I  ·  Onboarding the agent

Concentric rings of context

When Claude starts a session, the root CLAUDE.md is already in its context window — before you say a word. As it reads files, more CLAUDE.md's pull in automatically; as it follows links, deeper material loads on demand. The layering keeps the working set small while putting any needed knowledge within a hop or two.

II  ·  The substance

Eight pillars the project rests on

These are the conversations the codebase wants to have with the agent reading it. Each pillar points at a canonical entry doc (where to start), the supporting material (when you need more), and the code dirs it governs. The chip colors in the rings above match these pillars — so you can see at a glance where each pillar's docs sit in the context layering.

Cards

The core data format. YAML-frontmatter markdown with typed schemas — that's it.

Cards are the atoms. Everything else is just a way of moving them, reading them, or judging them. The simplicity is load-bearing.

→
docs/cards-as-markdown.md "RFC: Cards as Markdown + YAML Frontmatter" · 2553 lines

The deep design RFC. 2,553 lines. The first ~200 are the spine; skim the rest unless you're migrating.

  • docs/adding-schemas.md 192 lines Read this before writing a new card type. Saves an embarrassing amount of time.
  • docs/EXAMPLE_FILES.md 820 lines A browseable cookbook of every card shape in the system.
  • docs/migrations.md 160 lines What to run when the card format changes under a live box.

Connectors

The world dripping in. Sync external services into the box filesystem as cards.

Each connector's job is small: pull stuff, turn it into cards, leave them in the inbox. Boring on purpose.

Frontend

React UI on a small palette of primitives with strict rules about escape hatches.

The constraint is the feature: any agent that touches UI can only break it in narrow, recoverable ways.
