# Comparables roundup — Claude Code Channels, Khoj, Goose, Agent Zero, nanobot

*2026-07-04, second extension of the study (after Letta). Per-harness highlight scouts, not full dives: [scout-claude-code-channels](scout-claude-code-channels.md) · [scout-khoj](scout-khoj.md) · [scout-goose](scout-goose.md) · [scout-agent-zero](scout-agent-zero.md) · [scout-nanobot](scout-nanobot.md). Also considered and skipped: TrustClaw (security-first OpenClaw alt — revisit when the deferred security cluster reopens), elizaOS (persona/crypto), OpenHarness (pedagogical), IronClaw/ZeroClaw etc. (SEO-wave, unverified substance).*

## Claude Code Channels (Anthropic, research preview)
**Focus:** platform feature, not competitor — MCP servers that push events into a running Claude Code session. **Highlights:** official Telegram/Discord/iMessage bridges with pairing+sender-allowlists; ~100-line custom-channel contract; permission relay (approve tool prompts from chat, id-echo verdicts, first-answer-wins). **vs bbx:** potentially load-bearing — chat ingress and remote approvals native to the harness we rent; but chat-first/session-bound, so adoption must decide how events become cards. Triage row 19.

## Khoj
**Focus:** "AI second brain" — chat over your personal corpus (org/markdown/PDF/GitHub/Notion), commercially operated, FastAPI+Django, pgvector two-stage retrieval. **Highlights:** genuinely **bidirectional Obsidian integration** — under an explicit `write` permission the LLM emits SEARCH/REPLACE blocks the plugin applies to vault files with confirm/cancel UI; citations are clickable backlinks into the vault; two-tier sync (client mtime-diff, server content-hash diff); cron automations re-POST into their own chat endpoint and pass an **LLM "worth notifying?" gate** before emailing. **vs bbx:** the notes-sync + write-back mechanics are the reference implementation if we ever build an Obsidian connector (boxholder: "Obsidian is very close to us"); the notify-worthiness gate is a small steal for reminder delivery; their per-turn free-text memory-write loop is structurally inferior to typed cards + git — keep ours. Triage rows 21–22.

## Goose (Block)
**Focus:** production-shaped general local agent — Rust core, CLI/desktop/server/ACP, MCP-native extensions, real telemetry/eval infra. **Highlights (highest steal-density of the wave):**
1. **Recipes + `RetryConfig`** — shareable parameterized tasks with JSON-schema response contracts, sub-recipe composition, and *retry-until-a-shell-check-passes* with cleanup-on-failure: verified completion as a first-class primitive.
2. **`summon`** — subagents/recipes/personas behind two tools with async execution, non-destructive `peek`, cancellation, concurrency caps, TTL'd results.
3. **`SmartApprove`** — one-time LLM classification of each *new tool* as read-only, verdict cached: a cheap middle ground between bypass-everything and ask-everything.
4. **Two-tier context management** — continuous background tool-pair summarization + threshold compaction, with an agent-visible/user-visible message split so summarization never changes what the human sees.
**Counterpoint:** scheduler crash-safety is weak ("reset stale flags on boot, no resume, no catch-up") — the disciplined-org datapoint doesn't outclass our wakeup model. **vs bbx:** RetryConfig-style verified completion is the big idea (triage row 20); SmartApprove noted for whenever tool-narrowing reopens.

## Agent Zero
**Focus:** "a full Linux system for your AI agent" — Docker-shipped desktop/browser cowork agent; the deliberate heretic (hierarchy, self-modification, prompt-as-OS). **Highlights:** prompt-as-OS is real and deep (73 layered prompt files, profile overrides, live-reload); `behaviour_adjustment` self-modification merges edits via LLM+dedup rather than raw overwrite; fully automatic "solutions" memory (end-of-turn background pass mines problem/solution pairs into a vector area with consolidation, auto-retrieved every few iterations). **Verdict on the hierarchy question:** close reading *confirms* flat-agent skepticism — each agent holds one subordinate slot, communication is pass-a-string-down/get-a-string-back, no code-level depth cap (only a prompt rule), and the scheduler tool explicitly warns against recursive task creation. Structurally it's a synchronous subagent call wearing a hierarchy costume. **vs bbx:** solutions-memory is a vectorized cousin of skills-from-experience (we prefer the Hermes/skills shape); nothing else transfers.

## nanobot (HKUDS)
**Focus:** the minimal viable member of the category — 15 channels, WebUI, cron, memory, in ~11.5k core lines. **Highlights:** *instrumented minimalism* — a checked-in script measuring core-vs-surface line ratio (a discipline habit worth copying); message bus = two asyncio queues; cron = croniter poll over a JSON file; and the standout datapoint: **the LightRAG lab chose plain markdown + full-context replay over embeddings for their own product** — the strongest independent endorsement of the files-over-vectors consensus yet. Documented regret arc from free-text HISTORY.md to cursor-based history.jsonl (structure lane vs meaning lane). **vs bbx:** confirms which of our subsystems are essential vs elaboration; nothing to adopt beyond the measurement habit.

## What this wave changed

- **New consensus datapoints:** files-over-vectors (nanobot, from the RAG lab), flat-over-hierarchy (Agent Zero, by failing to be a counterexample), staged-write-back-with-confirm (Khoj's Obsidian mode ≈ our validate/commit gates).
- **Real additions to the idea pool:** Channels as platform-native ingress + permission relay (row 19), verified-completion/RetryConfig (row 20), notify-worthiness gate (row 21), Obsidian write-back reference (row 22), SmartApprove (noted, security-cluster-gated).
- **Standing conclusion unchanged:** nothing in the wider field does cards-first typed ingest, confidence-laddered triage, or git-as-activity-log. The differentiation thesis survives seven systems.
