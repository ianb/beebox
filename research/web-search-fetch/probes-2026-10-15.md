# First-hand fetch and search probes, 2026-10-15

Scripts and raw outputs were kept in session scratch (`probes/scripts`, `content`, `out`) and are not retained.

## Method and limits

- Date: 2026-10-15. All requests came from a residential IP on a macOS laptop. Boxes run on a Hetzner datacenter IP, which many sites treat worse. Nothing ran on the server, so every "ok" below is an upper bound for the box.
- One URL per category (n=1). A cell describes that URL, not the site.
- At most 3 requests per host per path, no retry loops. Exceptions: a second Wayback snapshot fetch and the Part B liveness check (one GET per cited URL).
- Public content only, nothing logged in. LinkedIn and Facebook use public page URLs. Searches for a stable public post URL on those two sites, on Quora and on TikTok returned none, so those four are a page or a guessed URL (marked).
- Verdict words: ok = the real content came back; partial = some real content (lede, caption, og tags) but not the full item; empty-shell = HTTP 200 with a JS shell and no content; blocked = 4xx or a block page; captcha = challenge page.
- Times are curl `time_total` unless stated. Browse time is the whole sequence (open, 1.5 s wait, get title, get text). WebFetch reports no timing.

### Part A notes

- `WebFetch` refuses reddit.com, nytimes.com, wsj.com and ft.com before any request ("Claude Code is unable to fetch from <host>"). It returns 402 for x.com.
- `WebFetch` gives "title only" answers for Facebook, TikTok and Instagram. It sees the server HTML, not the rendered page.
- Jina Reader returned its own "AbuseAlleviationError ... blocked until <time>" for x.com, tiktok.com and nytimes.com, caused by earlier abuse from other users. The block is per domain and time-limited, so Jina is intermittent for hot targets.
- Jina Reader got the Medium article and the Bloomberg lede with no key. These are the cases where it beat the headless browser, which hit Cloudflare and Bloomberg's robot check.
- `bin/browse` rendered the JS page, Instagram, Facebook, LinkedIn, YouTube and TikTok. It hit CAPTCHA or blocks on 9 of 15 URLs (Reddit, X, NYT, WSJ, Bloomberg, FT, Medium, Cloudflare test, Quora). Headless Chromium on a residential IP did not pass Cloudflare Turnstile or DataDome.
- Count of URLs with real content from at least one free path: 10 of 15 (Reddit via .rss/Arctic Shift, X via fxtwitter, Instagram, LinkedIn page, Facebook page partial, Bloomberg lede partial, Medium via Jina, JS page via browse, YouTube, TikTok via oEmbed). No free path returned NYT, WSJ, FT, Quora or the Cloudflare test page.

## Part B: search comparison

All AI-backed runs used the same prompt: the question plus "Use web search. Answer in under 300 words. Cite each claim with its source URL. Today is 2026-10-15." Model for the model-backed runs: `openai/gpt-5-mini` (OpenRouter), `gemini-2.5-flash` (Gemini API), `gpt-5-mini` (OpenAI Responses). OpenRouter used the `openrouter:web_search` server tool (the `web` plugin is deprecated) with `max_uses: 3`, `max_results: 10`.

Counting rules: URLs are the distinct URLs cited in annotations or written in the answer (for the two MCP servers, the result URLs). Gemini returns redirect links, so its domain count uses the source titles. "Forum" is a regex on the URL (reddit, community.*, forum, /threads/, discourse and similar), so it is approximate. The Claude Code WebSearch tool reports no latency or cost.

Tools:
- A = Claude Code WebSearch standard (X = extended mode, run for Q1 and Q4 only)
- B1 = OpenRouter tool, engine exa. B2 = OpenRouter engine parallel. B3 = OpenRouter engine native (gpt-5-mini native search).

## Observations

1. Fetch: curl with a Chrome UA, Jina Reader and the headless browser each covered cases the others missed. No single general path (paths 1 to 7) returned real content for more than 6 of 15 URLs. The URLs with no free route were NYT, WSJ, FT, Quora and the Cloudflare test page. The residential-IP headless browser passed none of the five challenge pages.
2. Per-host routes returned the content where general paths returned shells: Reddit (.rss, Arctic Shift), X (fxtwitter, syndication, oEmbed), TikTok and YouTube oEmbed, yt-dlp for transcripts, Medium RSS. All were under 1.5 s except yt-dlp (3.1 s).
3. Claude Code WebFetch has a client-side domain refusal list (reddit, nytimes, wsj, ft in this run) and reads server HTML only. It matched curl, or did worse, on every URL.
4. `archive.ph` and Wayback snapshot fetches rate-limited immediately (429), so archives were not usable at this request rate. This matches the earlier Reddit result of "no snapshot".
5. Search: results differ more in source mix than in count. Claude Code WebSearch returned 3 to 10 results per query, 0 Reddit, 0 GitHub in standard mode, and the least fresh forum set on Q1. The OpenRouter, OpenAI and Gemini tool calls cost $0.007 to $0.04 each and take 6 to 18 s. G and H cost nothing and take 0.8 to 2.1 s.
6. Exa-backed (B1, G) and Parallel-backed (B2, H) engines differ: Exa surfaced more recent forum and Reddit threads and personal blogs (Q1, Q2); Parallel surfaced more official and news pages (Q3). B2 produced 30 URLs on Q4 at twice the cost of other runs because the model searched more than once.
7. Single runs, one prompt per question, one model per vendor. Rankings between tools with similar counts are not statistically meaningful.

## Image check: `agent-browser`, WebSearch and WebFetch in boxes

- `agent-browser` is not on PATH on this machine. `bin/browse` wraps it (dev repo only). `beebox/docker/Dockerfile` installs pandoc, imagemagick, poppler-utils, ffmpeg, git, uv and similar.
