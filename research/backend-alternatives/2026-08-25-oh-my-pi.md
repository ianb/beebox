# oh-my-pi (omp) as a callback-box box engine

*2026-08-25. Research snapshot of [can1357/oh-my-pi](https://github.com/can1357/oh-my-pi)
at commit `eab72e88` / v18.0.5 (released the same day; near-daily cadence). Follow-up to
the July [harness survey](2026-07-18-alt-harnesses.md), scored against the same
eight-point runtime contract, and against the engine-adapter shape the
[Codex box engine](../../callback-box/docs/implemented-plans/codex-box-engine.md) established
on 2026-08-13. Question: could omp be a third box engine alongside Claude Code and Codex?
Not: is omp a good coding tool. Method: shallow clone, three parallel source audits
(headless surface; runtime contract; auth/maturity), with file:line evidence. Anything
the audits could not confirm in source is marked UNVERIFIED.*

## What it is

omp is a fork of Mario Zechner's `pi-mono` (four tools, a loop small enough to read)
taking the opposite bet: ~31 built-in tools, 60+ providers, a Rust native addon
(`packages/natives`: grep, PDF, audio, PTY, image), LSP and DAP tools, hash-anchored
"hashline" edits, in-process Python/JS cells, worktree subagents, an `advisor` model
role, a retain/learn/recall memory, and a Zed integration. MIT; copyright Zechner /
Can Bölük / Stencil Labs, Inc. (the company behind `omp.sh`). Repo created 2025-12-31;
27.4K stars, 30 contributors, 1,750 open issues. **Bun-only** (`engines.bun >=1.3.14`,
Bun APIs in core); no Node path. Prebuilt natives for linux-x64/arm64, darwin-x64/arm64,
win32-x64; a multi-stage `Dockerfile` exists.

## The auth finding (decisive)

omp's Claude Pro/Max login is a **deliberate Claude Code / Cowork impersonation**, verified in
source:

- Uses Claude Code's OAuth `client_id` (`9d1c250a-…`, base64-decoded at runtime,
  `packages/ai/src/registry/oauth/anthropic.ts:12-13`) against `claude.ai/oauth/authorize`.
- With an OAuth token present, `buildAnthropicHeaders()` sends
  `User-Agent: claude-cli/2.1.220 (external, claude-desktop)`, `x-app: cli`, and Cowork's
  `anthropic-beta` set (`providers/anthropic.ts:229-345`, constants in
  `providers/claude-code-fingerprint.ts`), and prepends the system line
  `"You are a Claude agent, built on Anthropic's Claude Agent SDK."` (`anthropic.ts:2907`).
- Refresh requests mimic Claude Code's refresh UA, with the comment "CC sends these on
  refresh but not on the initial code exchange".

That is the exact fingerprint Anthropic's January-2026 OpenCode block keyed on (system-prompt
prefix, header set, tool names — HN thread cited below), i.e. the path is engineered to pass
the check, and the July [policy note](2026-07-18-anthropic-policy-enforcement.md) already
established that every enforcement wave targets third-party harnesses on subscription auth.
Practitioner friction is visible in omp's own tracker (#6070 "anthropic subscription logouts
from omp daily or more often"; #980 Bedrock mis-prioritized over a valid subscription). No
press report names omp specifically as blocked (UNVERIFIED either way), but the posture is
one policy notice away from a dead path, and it is the opposite of the "single-tenant, user's
own login, ordinary use" argument callback-box's current posture rests on.

Other paths: Anthropic **API key** — clean. **ChatGPT/Codex OAuth** — uses Codex CLI's public
client id but identifies itself as `originator: pi`, `User-Agent: omp/<ver>` (honest, not
spoofed); still a third-party client on a subscription, the same informal-tolerance gray zone
the July [ChatGPT path note](2026-07-18-chatgpt-subscription-path.md) documented. OpenRouter,
Gemini API, Vertex, Ollama/llama.cpp/LM Studio/vLLM all built in. Role routing
(`settings.modelRoles`: `default, smol, slow, vision, plan, designer, commit, tiny, task,
advisor`) is real. An optional `auth-broker` + `auth-gateway` pair (`docs/auth-broker-gateway.md`)
centralizes refresh tokens server-side — relevant if a hosted deployment ever ran omp workers.
Vision is a per-model catalog attribute (`input: [text, image]`) plus a `vision` role; no
per-provider gap list exists (UNVERIFIED).

## Against the engine-adapter shape we actually have

The Codex engine plan settled how a second harness plugs in: a subprocess owns tools,
sessions and auth; a thin adapter maps cwd/model/images/structured output/resume/interrupt
into `src/core/agent/types.ts`'s `Agent` contract and the `claude-chat-types.ts` seam; native
history is read through the harness's supported API; the box's canonical `CLAUDE.md` /
`.claude/skills` / `.claude/rules` are mirrored by generation; the card validator runs
host-side because Codex app-server never executed hooks. Mapping omp onto that:

| Adapter concern | Codex (shipped) | omp (would be) |
|---|---|---|
| Process | app-server JSON-RPC/stdio | `omp --mode rpc` NDJSON/stdio, or in-process `createAgentSession` (Bun only, so subprocess in practice) |
| Session ids | refused; host maps | refused; host maps (same shape, `codex-run.ts` precedent) |
| Interrupt / steer / images | ✅ | ✅, plus steer/follow-up queueing that Codex lacks |
| Validator hook | host-side after `fileChange` items; finding fails the turn, no feedback to the model | **in-process `tool_call`/`tool_result`, fail-closed, feedback injected into the same turn** — this is the one place omp beats both shipped engines: the Claude plugin path lost same-turn advisory feedback when validation moved to PostToolUse hooks |
| Context mirror | `AGENTS.md → CLAUDE.md` symlink, rule skills generated | root `CLAUDE.md` invisible; needs `.omp/AGENTS.md` (or a `.claude/CLAUDE.md` copy per cwd) and `.omp/rules/*.md` generated from `.claude/rules` — a third generated surface |
| Sandbox | `danger-full-access` (workspace-write broke commits) | none to configure; same "instructions + host account are the boundary" posture |
| Usage | per-turn token event → `store/usage/codex-turns.jsonl` | per-entry usage + cost already in the transcript index |
| Runtime | `codex` binary | Bun + native addon per platform; daily releases, major bump 17→18 within the audit week; 1,750 open issues / 30 contributors |

Integration cost is the Codex adapter again, roughly: a medium adapter project, plus the Bun
runtime on every deploy target.

## Dispositions

- **REJECT — omp on the user's Claude subscription.** The impersonation path is a ToS
  exposure callback-box must not ship (the [policy note](2026-07-18-anthropic-policy-enforcement.md)'s
  "never centralize, never spoof" line; boxholder framing 2026-07-18 was resilience to policy
  events, and this path *is* the policy event). Claude via omp only makes sense on an API key,
  which Shape A ([provider-endpoint-config](../../issues/features/2026-07-18-provider-endpoint-config.md))
  reaches without a new engine.
- **LATER — omp as a third engine adapter, BYO non-Anthropic model.** It scores highest of
  any surveyed harness on the contract (5 ✅ / 2 ◐ / the auth ❌ is path-specific): real SDK,
  inline images, fail-closed in-process hooks with same-turn feedback, cost in the transcript,
  structured output that survives tools. What it buys over the shipped Codex engine is the
  model-agnostic loop (OpenRouter/Gemini/local) with one adapter, plus a validator that talks
  back to the model. Triggers: (a) a user actually asks for a non-Anthropic, non-OpenAI
  provider; (b) Shape A's spike shows the Agent SDK's loop does not survive a non-Anthropic
  endpoint; (c) omp stabilizes — a release cadence measured in weeks, and Node or a
  single-binary distribution. Filed as `issues/watch/2026-08-25-oh-my-pi-third-engine.md`.
- **ADAPT — same-turn validator feedback is the feature to copy, not the harness.** The Codex
  plan recorded losing advisory-in-turn feedback (validation now fails the turn). omp's
  `tool_result` rewrite shows the shape; on the Claude side the equivalent is the SDK's
  in-process PostToolUse returning additional context, which the plugin migration dropped.
  Worth a line in the port-hygiene issue
  ([chat-backend-port-hygiene](../../issues/code-quality/2026-07-18-chat-backend-port-hygiene.md))
  as an engine-contract requirement: "validator findings reach the model in the same turn".
- **REJECT — omp's `.claude` inheritance as a reason to prefer it.** It reads skills,
  commands and MCP faithfully; it does not read root `CLAUDE.md` or `.claude/rules` at all.
  Any engine needs the generated-mirror pass the Codex plan built; omp is not exempt.
- **REJECT — the batteries (LSP/DAP/hashline/cells/memory/Zed).** Box agents edit cards,
  not code; hashline is harmless (`edit.mode: replace` opts out) but nothing here is a reason
  to adopt.

## Watchlist

1. Anthropic action against the `claude-cli` fingerprint spoof in third-party harnesses
   (omp #6070-style logout churn is the leading indicator).
2. omp shipping a Node runtime or single binary; release cadence slowing.
3. Top-level `outputSchema` enforcement confirmed (probe: `createAgentSession({outputSchema})`
   with tools enabled, check the `yield` path fires).
4. OpenAI formalizing third-party subscription policy — shared trigger with the July
   Codex "LATER" item.
