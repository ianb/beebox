# Plain pi as a beebox box engine

*2026-10-18. Research snapshot of pi, the coding agent at
[earendil-works/pi](https://github.com/earendil-works/pi) (formerly `badlogic/pi-mono`;
npm scope now `@earendil-works/`), at tag `v1.3.0` (2026-10-15). Follow-up to the
[oh-my-pi review](2026-08-25-oh-my-pi.md), which assessed only the fork. Scored against
the contract the [Codex box engine](../../beebox/docs/implemented-plans/codex-box-engine.md)
met, in the shape of the [OpenCode scorecard](../opencode/engine.md). Question from the
boxholder: is plain pi complete enough on its own, in particular "can pi read AGENTS.md
and all that stuff and stream in and out in a way that fits well"? A capability beebox
would have to build itself counts as missing. Method: two source audits with file:line
evidence, plus two live SDK probes against pi's built-in fake model provider (no model
spend, no box content). Paths below are in `packages/coding-agent/` unless prefixed.*

## What it is

Mario Zechner's minimal coding agent: four default tools (read, bash, edit, write), a
TypeScript SDK, a JSONL RPC mode, and a terminal UI. MIT. It reached 1.0 on 2026-10-01 and
shipped 1.3.0 two weeks later. 116K stars, 347 open issues (oh-my-pi had 1,750 in August).
Runtime is Node ≥22.19; no Bun requirement and no native addon (image handling is wasm).
A single binary is available through `bun build --compile`. The npm install with
dependencies is 148 MB.

## 1. Instructions and skills

| Item | Verdict | Evidence |
|---|---|---|
| Root `AGENTS.md`, walk-up | ✅ | Per directory, first match of `AGENTS.override.md`, `AGENTS.md`, `CLAUDE.md`, from cwd up to `/` (`src/core/resource-loader.ts:185,232-270`). **Probed:** root nonce reached the model; with `AGENTS.md` removed, `CLAUDE.md` loaded instead. |
| Global file | ✅ | `<agentDir>/AGENTS.md`; `agentDir` is an SDK option (`resource-loader.ts:242`). |
| Nested `AGENTS.md` below cwd | ❌ | Not loaded on read, and pi's system prompt has no instruction to look for them. **Probed:** the model read `notes/deep/card.md`; `notes/AGENTS.md` never reached it. Codex has the same harness gap but its built-in prompt tells the model to obey scoped `AGENTS.md` files. For pi the host would append that instruction. Test boxes have ten nested `AGENTS.md` files. |
| `@file` includes | ❌ | No expansion (**probed**: the included nonce did not reach the model). The Codex adapter already expands top-level includes into developer instructions; the same output feeds pi's `appendSystemPrompt`. |
| `SKILL.md` skills | ✅ for `.agents/skills`, ◐ for `.claude/skills` | Discovers `.pi/skills` and `.agents/skills` (cwd and ancestors to the git root) plus home equivalents (`src/core/package-manager.ts:473-486,2454-2464`). `.claude/skills` is not discovered; `additionalSkillPaths` adds it. Progressive disclosure: name, description, path in the system prompt; the model reads the file (`src/core/skills.ts:355-390`). Frontmatter honored: `name`, `description`, `disable-model-invocation`. **Probed:** `.agents/skills` and `.pi/skills` descriptions reached the model; `.claude/skills` did not. The Codex track already generates `.agents/skills` symlinks and rule skills in every box, so pi picks those up unchanged. |
| Project trust gate | ◐ | CLI headless modes skip project-local skills unless trust is granted (`defaultProjectTrust: "always"`, `--approve`, or `trustOverride`). The SDK probe loaded them without extra config. |
| Path-scoped rules | ❌ | No `.claude/rules` or glob rules. The generated rule skills from the Codex track cover it, as they do for Codex. |
| System prompt | ✅ | `systemPrompt` (replace), `appendSystemPrompt` (array), override callbacks, `customSections`. A replaced prompt keeps context files and skills (`src/core/system-prompt.ts:145-181`). CLI: `--system-prompt`, `--append-system-prompt`. |
| Host control of discovery | ✅ | `noContextFiles`, `agentsFilesOverride`, `skillsOverride`, or a custom `ResourceLoader` (`resource-loader.ts:282-312`). |

Net: pi reads instructions at the same level as Codex. Every gap is one the Codex engine
already fills with generated files or expanded developer instructions, except nested
`AGENTS.md`, which needs one appended sentence. It is a step down from Claude Code, which
loads nested files itself.

## 2. Streaming in and out

| Item | Verdict | Evidence |
|---|---|---|
| Headless SDK | ✅ | `createAgentSession()` in-process from Node (`src/core/sdk.ts:192`). **Probed** on Node 24. |
| RPC | ✅ | `pi --mode rpc`, LF-delimited JSONL on stdio, one session per process with `switch_session` / `new_session` / `fork`; a TS `RpcClient` ships (`src/modes/rpc/`). Commands are typed; events are the SDK events forwarded, with no JSON schema. No HTTP server. |
| Typed events | ✅ | `agent_start/end`, `turn_start/end`, `message_start/update/end` (text, thinking, toolcall deltas), `tool_execution_start/update/end`, `queue_update`, `compaction_*`, `auto_retry_*`, `agent_settled` (`packages/agent/src/types.ts:514-540`, `src/core/agent-session.ts:196-236`). **Probed:** all of these fired in one run with a tool call. |
| Turn-end signal | ✅ | `agent_settled` means pi will not continue on its own; `agent_end` can be followed by retries or queued work. |
| Message while a turn runs | ✅ | `steer()` enters after the current assistant turn and its tool calls; `followUp()` enters after the run finishes. RPC `steer`, `follow_up`, `prompt` with `streamingBehavior`. A `prompt()` during a run without that choice throws. **Probed:** a steer sent during a running bash call reached the next model call; the follow-up reached the call after. Claude's SDK has only queue-style input; Codex has neither. |
| Interrupt | ✅ | `abort()` aborts the run and waits for idle; bash kills the process tree (`src/core/tools/bash.ts:114-144`). **Probed:** abort returned in 4 ms after a 500 ms wait; a `sleep 3; touch marker` command never created its marker. |
| Images in | ✅ | `images` on prompt, steer, follow-up (SDK and RPC); the `read` tool returns image blocks, omitted with a note on text-only models (`src/core/tools/read.ts:80-96`). **Probed:** a base64 PNG reached the model. |

Net: the streaming surface fits beebox better than Codex app-server and at least as well as
the Agent SDK. It is in-process TypeScript, so no hand-written JSON-RPC wrapper is needed;
the RPC mode remains if process isolation is wanted.

## 3. The rest of the contract

| Item | Verdict | Evidence |
|---|---|---|
| Session id | ✅ caller-chosen | `SessionManager.create(cwd, dir, { id })`. **Probed:** id `chat-coined-123` held across reopen. Not required (Codex lacks it), but it removes the host-side id map. |
| Resume after server restart | ✅ | Versioned JSONL tree (`CURRENT_SESSION_VERSION = 3`, migrations on load), `SessionManager.open(path)`, `list()`. **Probed:** a fresh session object over the same file saw the earlier steer and replies. In-flight runs are not resumed (same as both shipped engines); `packages/durable` does that but is a separate experimental harness. No delete API: the host removes the file. |
| Structured final output | ❌ | No output schema on a top-level run. The host would register a custom result tool (`customTools`, per-tool strict sampling via `constrainedSampling`, `terminate` to end the batch). That is beebox code. Triage, chat review, retro, migration repair and procedure model validation use `invokeStructured`. |
| `maxTurns` / `maxBudgetUsd` | ◐ | Neither exists. The host counts events and calls `abort()`; the Codex adapter already approximates `maxTurns` the same way. Because pi reports USD cost per message, a host-side budget cutoff is possible, which Codex cannot do. |
| Unattended permissions | ✅ | No approval gates in core (`docs/security.md`); nothing waits on a human in headless modes. No sandbox: same posture as Codex `danger-full-access`. |
| In-process hooks | ✅ | Extension `tool_call` can block or rewrite input, fail-closed on throw; `tool_result` can rewrite content, fail-open; `pi.sendMessage(…, {deliverAs: "steer"})` puts a validator finding back into the same run. This restores the same-turn validator feedback that both shipped engines lost. |
| Token / cost | ✅ | Per-message input, output, cache read/write, reasoning, and USD cost on `message_end` and in the session file; `get_session_stats` (`packages/ai/src/types.ts:451-472`). Source only; the fake provider reports zeros. |
| Transcript readability | ✅ | Documented JSONL format (`docs/session-format.md`) and typed `SessionManager` reads; no private-format scraping. |
| Compaction | ✅ | Automatic with configurable thresholds; `compaction_*` events and a transcript entry. |
| Auth | ◐ | API keys for Anthropic, OpenAI, Google, Bedrock, Vertex, Azure, OpenRouter, Groq, Mistral, DeepSeek and others; credentials injectable through `ModelRuntime` (`authPath`, custom store) or env. **Claude Pro/Max login impersonates Claude Code**: Claude Code's OAuth client id, `user-agent: claude-cli`, `x-app: cli`, a forced "You are Claude Code" system prefix, and tool renaming (`packages/ai/src/api/anthropic-messages.ts:1061-1062,1142,1228-1232`). Same finding as oh-my-pi; that path is out. ChatGPT login uses Codex's OAuth client but identifies as `originator: pi`, the same gray zone as before. |
| Footprint | ✅ | Node ≥22.19, no Bun, no native addon. |
| Stability | ◐ | No semver or API policy. 1.x breaking changes so far are extension-level (`before_agent_start` semantics) and provider renames; the SDK session surface has held. Five releases in 15 days. |

oh-my-pi adds batteries (LSP, worktree subagents, 31 tools) that box agents do not need,
and costs a Bun runtime. Its one contract advantage, the `yield` structured-output tool, is
the piece pi lacks. OpenCode has native structured output and `.claude/skills`, but its
session identity, storage durability and unanswered-permission hang were the reasons for its
August *later*.

## Verdict

**pi as-is meets the boxholder's bar.** It reads `AGENTS.md` (walk-up, `CLAUDE.md`
fallback) and `.agents/skills` natively, takes an appended system prompt, and has the best
streaming surface of the three: a Node SDK with typed events, steer and follow-up during a
run, clean abort, and image input. Plain pi is a finished harness, not a toolkit that needs
oh-my-pi or OpenCode on top.

One contract item is missing and would be beebox code: a structured final answer for
`invokeStructured` callers. It is a small custom tool through pi's supported extension API,
not a lower-level harness, but by the stated rule it counts as missing. Everything else the
Codex engine needed (include expansion, generated rule skills, host-side turn counting) is
already built and applies to pi as-is. Nested `AGENTS.md` needs one appended instruction.

## Dispositions

- **LATER — pi as the third box engine, BYO API key.** It replaces oh-my-pi as the
  candidate: same SDK lineage, Node instead of Bun, caller-chosen session ids, a fifth of
  the open issues, no batteries to disable. Estimated size: smaller than the Codex adapter,
  because it is in-process TypeScript with typed events and no JSON-RPC wrapper, plus a
  result tool for structured output and a validator extension. Re-check triggers are in
  [pi third-engine watch](../../issues/features/2026-10-18-pi-third-engine.md).
- **REJECT — pi on a Claude subscription.** The login impersonates Claude Code, as
  oh-my-pi's does.
- **ADAPT — steer-style validator feedback.** pi's `tool_result` plus
  `sendMessage(…, {deliverAs: "steer"})` is a second example of the same-turn feedback the
  oh-my-pi review asked to record in
  [chat-backend-port-hygiene](../../issues/code-quality/2026-07-18-chat-backend-port-hygiene.md).
  No new action beyond that.
