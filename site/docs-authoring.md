# Writing agent docs

This is the content-author's guide to `site/docs/` and `site/docs-manifest.yaml`
— the corpus published at `/docs/` and indexed by `llms.txt`, read by a general
chatbot on behalf of someone deciding whether to use Bee Box. Full design and
rationale: `../beebox/docs/plans/agent-docs.md`. Mechanism: `docs.ts` and its
`site/CLAUDE.md` section.

## Where a page lives

Everything under `site/docs/` mirrors exactly where it will publish under
`/docs/`. `site/docs/capabilities/gmail.md` becomes `/docs/capabilities/gmail.md`.
Files directly under `site/docs/` (no subdirectory) must be numbered spine
files (`01-what-bee-box-is.md` … `11-making-it-yours.md`) — everything else
belongs in a directory.

The directories: `capabilities/`, `concepts/`, `install/`, `security/`,
`architecture/`, `design/`, `compared/`, `contracts/`, `dev/` (the
contributor entry point, see below), plus the generated `reference/` and
`reference/cards/` (never author into those — see below).

## Frontmatter

Every page needs:

```yaml
---
description: "One line. Becomes its row in the directory's index.md."
---
```

A page under `compared/` additionally needs:

```yaml
compared:
  date: 2026-07-14
  subject: "OpenClaw v0.9 (commit or version looked at)"
  beebox: "commit abc123 or a date"
  looked-for: [memory model, channels, scheduling, security posture]
  not-looked-for: [pricing, hosted offerings, community size]
```

The build prepends a caveat block generated from this frontmatter — don't
write the caveat by hand, and don't put `compared:` on a page outside
`compared/`. A comparison older than six months gets an automatic "Stale"
line; there's nothing to do about that except write a fresh one.

## Body

Plain markdown. The first `# Heading` is the page's title (used in `llms.txt`'s
spine listing — only the spine's title comes from the body; every other
index uses the filename). No Markdoc tags — this is raw markdown served
as-is, not rendered through the site's card pipeline.

## Links

Write links as relative paths within the published tree: `../concepts/cards.md`
from a directory page, `gmail.md` between siblings, `01-what-bee-box-is.md`
from a directory page up to a spine file. The build validates every link
resolves to a real published file (including a directory's generated
`index.md`) — a link to something not in the manifest, not yet authored, or
misspelled fails the build with the exact target that didn't resolve.

No links into the repo's `plans/`, `issues/`, `research/`, or similar internal
material — there is nothing there for this corpus, and an authored link there
will fail the same way any other unresolvable link does (promoted docs, by
contrast, get those links flattened automatically — see `site/CLAUDE.md`).

## Adding a new directory

A directory with files needs an index stub: `site/docs/<dir>/index.md` with
just `description:` frontmatter (no body needed — only the description is
used). The *published* `index.md` — the actual file listing — is always
generated by the build; never write one by hand. A directory with files and
no stub fails the build; a directory with no files yet is simply skipped
(missing from `llms.txt`'s directory list) — that's fine mid-work.

## A directory's own README.md

A `README.md` inside any directory (not just the corpus root) is that
directory's preamble — never a published page, never listed in its
`index.md`. Frontmatter is `description:` (one line) and an optional
`start-here:` list of filenames in that directory. `site/docs/dev/README.md`
is the one place this is consumed today: it becomes `dist/llms-dev.txt`'s
summary and body, and `start-here:` orders that entry file's `## Start here`
section (everything else published under `dev/` falls into `## Files`,
sorted). No `dev/README.md` means no `llms-dev.txt` — that's legal mid-work,
not a build failure.

## Promoting a repo doc instead of writing new prose

If a doc already in `beebox/docs/` (flat, or under `design/`/`architecture/`)
says the thing well, add a line to `site/docs-manifest.yaml` instead of
re-writing it:

```yaml
- source: beebox/docs/glossary.md
  publish: concepts/glossary.md
  description: "Bee Box terms, one line each."
```

Adding that line *is* the review — someone read the source doc and judged it
fit for a stranger. The loader refuses any `source` outside `beebox/docs/<flat
file>.md`, `beebox/docs/design/`, `beebox/docs/architecture/`, root
`README.md`, or the three individually admitted files `beebox/CLAUDE.md`,
`beebox/code-style.md`, `beebox/frontend.md`; and any `publish` outside the
directories above (which also includes `dev/`, for contributor-facing
promoted docs) — regardless of what's written in the manifest. A promoted
doc's own internal links are rewritten automatically (see `site/CLAUDE.md`)
— you don't need to touch them.
