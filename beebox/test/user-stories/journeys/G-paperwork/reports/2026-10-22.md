## Harness defects

- **H1 — `bin/browse snapshot` hung on the unstarted chat, and a concurrent walker's cleanup killed it silently.** Two defects.
  - *The hang.* Upstream `agent-browser` 0.27.0 `snapshot` does not return on some unstarted-chat pages. Reproduced in session `aa-g-1` on a new chat in this box (`/chat?session=c78c9673-…`, "New conversation", openers in the chat column): `snapshot -i`, plain `snapshot`, `snapshot --json`, and `snapshot -s textarea` all hung. Left alone, upstream gave up after 154 s with `✗ Failed to read: Resource temporarily unavailable (os error 35) (after 5 retries - daemon may be busy or unresponsive)`. `eval`, `screenshot`, `click`, and `get` kept working (the walker's experience). The same URL in a fresh session (`aa-g-2`), where the openers render on the Box card instead, worked in 1 s; so did unstarted chats in the F, H, I, and B boxes. The trigger is page state, not the URL: removing `#bbx-nav-session`, `#bbx-nav-place`, or `main` from the DOM cleared the hang; removing the empty-chat block, the body-level autosize `textarea`, `#bbx-nav-voice`, or `#bbx-nav-profile` did not. The exact element is not pinned. The B-inventory walker hit the same thing in the same window (B report H1).
  - *The silent exit.* Every `bin/browse` call first runs `reclaimWorktreeBrowsers` (`browse/src/cli.ts:109-118`), which SIGTERMs any process in this worktree whose command matches `node_modules/agent-browser/`, has no pidfile, and is over 60 s old (`bin/process-cleanup.ts:456-479`, `classifyAgentBrowser` at `:282-294`, `MIN_ORPHAN_AGE_SEC` 60). That match includes another session's in-flight CLI client, not only orphaned daemons. The killed client closes with a null code; `annotatedSnapshot` (`browse/src/act.ts:151-158`) then writes the empty stderr and returns 1. Reproduced: a hung `snapshot` in `aa-g-1` was still running at 70 s and ended with rc 1, 0 bytes of stdout and stderr, 5 s after one `get url` in session `aa-g-2`. During the walk, the other six walkers ran `bin/browse` every few seconds, so each of the walker's seven snapshots died at 62–94 s with no output.
  - Cost: 8 minutes before the first message, and no refs for the whole walk (the walker used `eval` to list `bbx-` ids). The coordinator's later `snapshot -i` worked because the chat had started by then.
  - Fix: (1) the reaper must not kill CLI clients: match only daemon processes, or spare any process whose parent is a live `bin/browse`; (2) `annotatedSnapshot` and the runner must report a signal ("killed by SIGTERM after N s") instead of an empty exit 1; (3) bound `snapshot` with `timeoutMs` and say "snapshot timed out; `eval` and `screenshot` still work"; (4) find the upstream hang (start from the unstarted chat with openers in the chat column, session `aa-g-1`). The kill is fixed in `21e9872db`. Filed: [browse-command-killed-by-a-signal-exits-1-silently](../../../../../../issues/closed/bugs/2026-10-22-browse-command-killed-by-a-signal-exits-1-silently.md) (item 2); the upstream hang (item 4) is noted on [browse-daemon-wedges-on-animated-canvas](../../../../../../issues/closed/bugs/2026-07-14-browse-daemon-wedges-on-animated-canvas.md).
