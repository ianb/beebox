## Harness defects

- **H1 — the situation names a calendar month that has passed.** `A-lending/journey.yaml:41` says the campsite is "booked for mid-October". On 22 October the agent rightly asked whether the trip had already happened, and the walker had no answer in the situation, so it invented "mid-November". The stove's deadline, the chase order, and the first todo all follow from that invention. `watch_for` (`journey.yaml:100,115`) also says "October deadline". Fix: state the deadline relative to the walk ("in about three weeks"), or have `prepare` substitute a date computed from the walk date. Fixed in `6f1a200b9`.
- **H2 — the walker invents outcomes.** Besides H1, the walker reported Bram's answer ("he doesn't have the tape measure"), which the situation never gives, and moved The Overstory's arrival from tomorrow into the same evening. The brief named the Bram case; the walker's own notes say "pretend tomorrow happened". The app's handling was right for the input, but the tape-measure test ("push on the doubt") ended in a resolved fact, and the doubt was tested only once (row 30). Fix: the walker prompt should say that the person knows only what the situation says, must not invent replies from other people or the passing of time, and may say "I don't know yet" to the app. Fixed in `6f1a200b9`.
- **H3 — the walker clicks stale refs.** One `@e27` click after a tab change, without a new snapshot, opened a different card, and the notes then said the front card's button was not reachable (row 37). The prompt already says to re-snapshot; the walker skipped it in a chained command. Fix: `bin/browse` could refuse a ref after a navigation or tab change in the same chain, or the prompt could forbid chaining a ref click after another action. Filed: [browse-clicks-a-ref-it-has-called-stale](../../../../../../issues/bugs/2026-10-22-browse-clicks-a-ref-it-has-called-stale.md).
- **H4 — walkers share `/tmp/x`.** The A walker's wait loop wrote each snapshot to `/tmp/x` and grepped it for the stop button (eight times, 12:40:36–12:48:52). The I-deciding walker wrote the same file at 12:40:27. With concurrent walks, one walker's loop can read another's snapshot and stop waiting early or late. No effect was seen here: every A loop ended after its turn completed. Fix: give each walker a scratch path in its run directory in the prompt (for example `<run-dir>/tmp/`), or give `bin/browse` a "wait until the agent finishes" command so no file is needed. Fixed in `6f1a200b9`.
- **H5 — the walker reads accessible names and hidden regions as visible UI** ("Box", "Workspace" in row 2). Same as 2026-10-09 H4. Filed: [walker-prompt-gaps-from-the-2026-10-22-walks](../../../../../../issues/docs-and-chores/2026-10-22-walker-prompt-gaps-from-the-2026-10-22-walks.md).
