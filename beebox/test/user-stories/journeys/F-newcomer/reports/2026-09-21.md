## What the walk achieved

Collection found six box commits: a household jobs card, its cupboard-handle
completion, a Spanish note, two Spanish practice updates, and a final `lista`
result. State verification confirms exactly two new cards and six commits:
the household handle is done with two jobs open, and the Spanish note contains
the soup mistake and the later `lista` practice. A separate filesystem check found two untracked chat cards containing
metadata only; collection itself records only their directory; the UI's cross-chat recall independently
matches those durable facts. The chat directory remains untracked. The two session IDs also appear in
`.beebox/chat-session-history.json`; their user-message counts were five and
three. This inspection is separate from `collect.ts` output. No account,
reminder, invitation, external message, real upload, or voice interaction was
tested.

The person learned that chat can retain household context and a specific
Spanish difficulty, and would return for short Spanish practice. They found
the task list less convenient than checkboxes, could not establish Search,
could not understand Google access scope, and elicited a correction to an unsupported calendar promise. The correction’s
broader reminder/scheduler explanation was not independently verified.

## Harness and verification notes

The only substantive walk interruption was the two refused Search fills. The
harness native-label omission is now fixed and independently checked with a
real C Search fill and five browser guard probes. Those checks are ad hoc,
not durable automated regressions. The eight existing doctests cover snapshot
escaping/annotation, not the label/DOM behavior. Typecheck and lint also pass
but do not parse JavaScript inside the generated script string.
That proves the harness path after the walk; it does not prove F Search's
product result behavior. Stale-reference warnings on fresh no-id controls did
not prevent intended clicks. No microphone interaction occurred, and no
microphone claim is a product finding.

## Verified mechanisms and issue dispositions

Review corrected the first-screen diagnosis: suggestions already exist. The
fixture briefing contained “Let me tell you what this box is for.” and “What
can you do?”; `InteractiveChat-messages.tsx:265–270` can render them. However,
`resolve-conversation.ts:47–70` reserves a fresh Claude session UUID;
`BoxConversationShell.tsx:83–94` passes that ID through, and
`InteractiveChat.tsx:75–77` requests openers only for literal `"new"`.
The ordinary box-root route redirects to `/chat` without a supplied ID. This
is a [product reservation/gating mismatch][openers], not harness-created old-session
navigation and not a wholly absent orientation feature.


The [first-screen issue][first], [metadata issue][metadata], and
[navigation issue][sidecar] received dated F evidence. The calendar promise
became a [separate output-reliability issue][promise]. New issues also retain the [unavailable ticks][ticks], [completed agent
bookkeeping][bookkeeping], and [Calendar setup copy][setup] findings.
No product fix was made.

Task annotations and The Plate are intentionally read-only in v1 (`Todo.tsx`,
`TodoViewCard.tsx`); the generated “tick them off” prose promised a control
that these surfaces do not provide. The completed agent-assigned annotation
in the Spanish card also renders by design, exposing bookkeeping to its reader.
Calendar Settings displays its query error verbatim (`CalendarSection.tsx:73–83`),
including agent-directed configuration instructions. The fixture has no
`googleServices` key; missing services are disabled by `core/box/config.ts`.
OAuth host availability was also shown as unavailable in screenshot 07.

Per-conversation panel persistence exists in `sidecar-tabs-storage.ts:72–109`.
It is consistent with the observed return of prior panels but does not prove
which transition caused each reappearance. No panel implementation was changed.

[Labelled visual evidence](http://127.0.0.1:3230/journey-walk/journey-f-finding-a-reason-to-return/)
retains five screenshots: empty arrival, promised ticks, useful recall,
calendar promise, and its withdrawal. This is an FYI exhibit, not an approval request.
