## Harness defects

- **H1 — `box.setup` leaves the root question pending on a box with a past.** The first view, the composer placeholder, and the "1 question waiting" count all ask what the box is for (rows 2, 23, 37). In real use Tomas would have answered it in August. Fix: H's setup answers or removes `_bookkeeping/questions/what-to-keep-track-of.question.card` (and replaces the stock opener), or prepare gets a `box.rootQuestion: answered` option for journeys whose box has a past. Fixed in `6f22f4d8d`.
- **H2 — the box was built from a draft of the journey.** The box's guest list differs from the committed `journey.yaml`. Prepare does not record which journey text it used. Fix: prepare writes a hash (or copy) of `journey.yaml` into the run directory, and `collect.ts` warns when it no longer matches. Fixed in `6f22f4d8d`.
- **H3 — the box's name and history do not look like Tomas's box.** The root label is the run slug (row 1). The "Initialize Bee Box" commit is dated 22 Oct and is the parent of commits dated August and September, so `git log` reads out of order. Fix: setup sets the root landmark's `navigation.label` (for example "House") and prepare dates the init commit before the setup's first backdated commit. Filed: [journey-boxes-look-like-test-runs](../../../../../../issues/code-quality/2026-10-22-journey-boxes-look-like-test-runs.md).
- **H4 — the walker's shell ate `$1`.** Fix: the walker prompt tells walkers to put `fill` text in single quotes. Fixed in `6f22f4d8d`.
- **H5 — no identity for the walker.** The browse key is not a signed-in user, so messages carry no `user` attribute and commits carry the run's git identity. This journey is about a second person, so it cannot test who-did-what (rows 32, 53). Re-encounter of the open browse-key issue. Fix for this journey: prepare creates a second local user and browse signs in as that user. Re-encounter noted on [browse-key-is-not-a-signed-in-owner](../../../../../../issues/bugs/2026-10-09-browse-key-is-not-a-signed-in-owner.md).
- **H6 — `clock.ts` gives no hint when a turn is in progress.** "No completed first-response intervals" is right but reads as broken mid-turn (row 12). Fix: say "no reply has started yet" when the newest user message has no assistant text, or tell walkers to run it after a reply appears. Fixed in `673026da8`.
- **Time of day.** The walk ran in the box's morning; the situation is an evening. The agent was told "(morning)" and still wrote "evening" from the walker's "tonight". No effect on the walk. Filed: [walker-prompt-gaps-from-the-2026-10-22-walks](../../../../../../issues/docs-and-chores/2026-10-22-walker-prompt-gaps-from-the-2026-10-22-walks.md).
- **Stale refs** (rows 8, 45): the known pattern. Chat links have no `bbx-` id, so the walker has to use refs. Filed: [browse-clicks-a-ref-it-has-called-stale](../../../../../../issues/bugs/2026-10-22-browse-clicks-a-ref-it-has-called-stale.md).
