- The old `prepare.ts` could not safely replace the current harness: it uses
  retired box paths and commands. Lowercase slugs, readiness checks and evidence
  retention are already covered by `2014c37b6`, with stronger current-root setup.
- The old asset-specific explanation was recovered as conditional wording in
  the walker template. Asset-free walks are no longer promised photographs.
  The prompt actually used by C remains frozen in its run directory.
- The old scheduler warning was recovered as a verification boundary, without
  asserting that today's scheduler uses the old registry path or that a valid
  schedule proves delivery.
- The `delay=` to `in=` documentation correction was recovered after checking
  the current parser. No timer implementation was changed.
- Repository references use `beebox/`; original runtime paths, observed UI
  wording and historical source line numbers are retained as historical facts.
  The retired configuration-directory literal is described rather than copied
  to satisfy the repository name guard; the source branch retains the original.

## Limits and validation

The original report calls its 6.1 minutes across nine turns "waiting". The old
instrument measured first assistant text, which may be a preamble, and supported
only its Claude transcript roots. Read that number as a historical partial
first-text metric, not completion latency. Its 34.7-minute screenshot span
includes operator work. Capture was owner-auth blind, reminder delivery was not
verified, and microphone draft loss was not independently reproduced.

The raw copies and Git bundle are local, ignored worktree artifacts, not an
independently backed-up archive. They can be lost when worktrees are removed.
Agree where raw journey evidence should live before any worktree cleanup; the
tracked reports and issues survive through Git, but the raw files do not.

Recovery does not mark any historical issue fixed merely because adjacent work
landed. It also does not reopen closed issues merely because old observations
were recovered. No product fixes, new live messages or journey reruns were made.
