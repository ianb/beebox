# Publish the TTS model comparison on beebox.run

The TTS model comparison (19 speech models, 7 test texts, 289 renders) exists
only as a local dev-dashboard exhibit. This plan moves its data and tooling
into `research/tts-model-comparison/` and publishes it as an unlisted
beebox.run page with playable audio, linked from "For developers" beside the
AI audio understanding comparison.

**Issues addressed:** none filed. Searched `issues/` for `tts`, `comparison`,
and `audio-bakeoff`: related but not resolved by this work are
`issues/exploration/2026-10-20-tts-inline-delivery-markup.md` (the page's
"how direction was delivered" section draws on it) and
`issues/docs-and-chores/2026-10-17-public-provider-list-drifts-from-code.md`
(about the provider list, a different page).

## Design

No design section: this is a public static web page about development, not
a change to what a person meets in the box. Page structure copies the shipped
audio comparison page.

## Smallest fix and budget

Smallest fix: copy the exhibit's audio into `site/assets/`, hand-write a card
with raw links to the files. It fails on two counts: Markdoc has no audio
element, so each take would be a download link, not a player; and 287 files in
mixed MP3/WAV at 82 MB is too much to add to the repository.

Chosen shape, three tracks:

1. Site: an `{% audio %}` tag, more model vendors for the pill, a build check
   that every audio source exists. About 80 source lines, 60 test lines.
2. Research: `research/tts-model-comparison/` with `results.json` (moved),
   `lib.ts` (types, the transcript check), `render.ts` (a provider-adapter
   renderer, Voxtral the one implemented adapter), `publish.ts` (transcode
   audio, write the site card). About 400 source lines; README about 90 lines.
3. Page: the card, generated by `publish.ts` from `page-template.md`
   (authored prose, about 120 lines) and `results.json` (generated, about
   700 lines). One link line on "For developers".

Total authored change about 750 lines plus about 700 lines of generated card
and ~13 MB of audio. Not a BIG CHANGE.

## Stated preferences this plan trades against

- `site/AGENTS.md`: *"no external requests at view time … The output in
  `dist/` is the whole product"*. The audio is local files under `dist/`.
- `site/AGENTS.md`: *"The build fails closed: … a broken internal link, or a
  missing source stops it."* A missing audio file must fail the build too.
- `site/AGENTS.md` "Authorship is explicit": the card's `authorship` block
  names the agent's drafting and the boxholder's direction.
- Root `AGENTS.md`: *"Write code in TypeScript"*. The scripts are `.ts` run
  with `tsx`, as the audio bakeoff's are.
- Repo size against completeness. Git has no LFS files today (`git lfs
  ls-files` prints nothing) and the pack is 243 MB. Keeping every take as
  Opus at 32 kbit/s adds about 13 MB (5%). Dropping takes would save at most
  about 8 MB (pacing repeats are 2,100 of 3,363 seconds), and the repeats are
  what the pacing clip is for. Keep them all.

## Ontology

- **Model**: one speech model on one route, id e.g. `voxtral-mini-tts-3`
  (exists in `results.json` `models[]`). Gains `name` (display) and `vendor`
  (pill class). Not a provider: two Gemini routes are two models.
- **Clip**: one test text, id e.g. `3-sarcasm` (`clips[]`), with `listenFor`
  and optional `direction`.
- **Render**: one model × clip × variant × repeat (`renders[]`). Variant is
  `plain`, `directed`, or `markup`. Unchanged.
- **Take** (page word): a render as heard on the page. Same thing as a render;
  the code keeps "render".
- **Transcript check**: `extraWords`, `missingWords`, `leakedWords` on a
  render. Unchanged.

## Tracks / scope

### 1. Site: audio tag and vendors

- What: `{% audio src="/assets/tts-comparison/<file>.webm" /%}` renders
  `<audio controls preload="none" src="<base>assets/…">`. `VENDORS` adds
  `microsoft`, `fish`, `minimax`, `elevenlabs`, `cartesia`, `deepgram`,
  `xai`, `mistral`; pills without a vendor color use one neutral style.
- Why: Markdoc drops unknown HTML; there is no way to embed a player today.
- Direction: `src` must start with `/assets/`; anything else fails
  validation. `rewriteLinks` resolves it with `resolveInternalHref` and puts it
  in a separate `assetTargets` list; `build.ts` fails if any target is not a
  file in `dist/`. The twin strips the tag (catch-all) and keeps the text.
- Vocabulary lock-ins: tag name `audio`, attribute `src`.
- First chunk: tag, rewrite, build check, tests in `evaluation-tags.test.ts`
  and `box-export.test.ts`.

### 2. Research directory

- What: move `results.json` into `research/tts-model-comparison/`, add `name`
  and `vendor` per model, write `lib.ts`, `render.ts`, `publish.ts`,
  `page-template.md`, README.
- Why: the exhibit store is outside git and its generator for 18 of the 19
  models is lost. The comparison should be re-runnable like the audio bakeoff.
- Direction: `render.ts --model <id>` renders every clip for one model through
  a `Provider` adapter (`synthesize(input, options) → wav/mp3 bytes`),
  transcribes take 0 of each clip with `gpt-4o-transcribe`, runs the transcript
  check, and replaces that model's rows in `results.json` only when every job
  succeeded; otherwise it prints the failures (status and a fixed category,
  never a response body) and writes nothing. Original audio goes
  to `TTS_AUDIO_DIR` (default: the exhibit's `audio/`). Only the Voxtral
  adapter is implemented; the README says the other 18 need adapters written
  before they can be re-rendered. `publish.ts` transcodes every render's file
  to mono Opus 32 kbit/s WebM in `site/assets/tts-comparison/` (skipping
  up-to-date files, deleting files no render names) and writes the card.
  Keys: a small reader of the machine secret store file in `lib.ts` (root
  typecheck excludes `beebox/`, so importing `loadSecretStore()` would pull
  beebox into it); never printed. `loadResults()` validates the schema,
  unique model/clip/variant/repeat keys, and that each file name is
  `<model>__<clip>__<variant>__<repeat>.<ext>`.
- First chunk: move data, `lib.ts`, `publish.ts` transcode half.

### 3. The page

- What: `site/cards/develop.attach/tts-comparison.doc.card`, unlisted,
  `kind: generated`, linked from `develop.site-page.card` beside the audio
  comparison.
- Sections: what this is for; the models (route, voice, list price, render
  date); how it was tested (seven clips, plain vs directed vs markup, how each
  backend takes direction, the transcript check and its limits); clip by
  clip: a `sample` box with the text and what to listen for, then per model
  the plain take(s), any directed or markup take with the exact text sent,
  and the transcript check.
- Transcript state per take: matched, the recorded extra/missing/spoken
  words (no threshold), or "not transcribed" for repeats 1-4 of pacing.
- Facts stated as they are: renders on 2026-09-16, 2026-09-23 and 2026-10-20
  (from the audio files' dates, recorded per model as `rendered`);
  Voxtral was transcribed with `gpt-4o-transcribe` and the transcriber for
  the earlier rows is not recorded; Voxtral uses a different voice (Sarah)
  from the female voices picked elsewhere and has no instruction field;
  Gemini 3.1 via OpenRouter timed out on two of five pacing takes; prices are
  list prices, some converted.
- No verdicts: nobody graded these takes, so the page gives none.

## Could this be simpler?

Simplest: hand-write the card once and transcode once with a shell loop, no
`publish.ts`. It fails the re-runnable requirement: adding one model would
mean hand-editing seven sections and twenty audio rows, and 289 hand-written
rows will drift from `results.json`. The generator buys one source of truth.
`render.ts` with a single adapter is the smallest form of "re-runnable" that
is honest about the lost generator; writing 18 adapters from scratch is out of
scope.

## Failure modes

| What can fail | Test exists? | Handling exists? | Clear-or-silent? |
|---|---|---|---|
| Card names an audio file that was not transcoded | build test (new) | build fails naming the file | clear |
| `src` outside `/assets/` or absolute URL | tag test (new) | validation error with line | clear |
| Base path not applied to `src` (page under `/beebox/`) | build test (new) | `resolveInternalHref` | clear |
| Opus/WebM not playable in Safari | manual WebKit check | none | silent → checked at screenshot step |
| `publish.ts` leaves orphan audio after a model is removed | none | deletes files no render names | clear (prints count) |
| A key leaks into `results.json` or console | none | key stripped from error text; only status/ms logged | — reviewed in diff |
| Two failed renders (no file) | publish logic | rendered as "failed: timeout" text | clear |

## Agent-flow / user-flow edge cases

- Wrong tag: an agent writes `<audio>` HTML; Markdoc escapes it as text,
  visible on the page. ADDRESSED by the README naming the tag.
- Hand-edit drift: someone edits the generated card. ADDRESSED by a
  frontmatter comment naming `page-template.md` and `publish.ts`.
- Fabricated value: the page shows no grades, only measured fields.
  ADDRESSED.
- Stale ref, concurrent agents, migrations: not applicable; static files.

## NOT in scope

- Adapters for the 18 non-Voxtral models: the original generator is lost;
  rebuild them when a re-run needs one.
- Grading takes (verdicts): needs a listener's judgment; the boxholder has not
  asked for it.
- Latency and cost tables: the exhibit has them, but the 2026-10-04 latency
  numbers in `tts-backend-selection.md` are the measured ones; repeating
  single-run timings invites wrong conclusions. Per-render cost shown inline
  is also left out; list prices are given.
- Publishing: landing on `main` and pushing needs the boxholder's yes.

## What will hold this after it ships

`site` node tests: the `audio` tag (validation, base rewrite) and the build's
missing-audio failure. The generated card is checked by every site build. The
research scripts are covered by root typecheck and lint, and by running
`publish.ts` (it is idempotent: a second run changes nothing).

## Implementation order

1. Site tag, vendors, build check, tests.
2. Research directory: move data, `lib.ts`, `publish.ts` transcode.
3. `page-template.md` and card generation; link from "For developers".
4. `render.ts` with the Voxtral adapter; dry check (`--dry-run` lists jobs
   without calling the API).
5. Build, screenshots at desktop and phone width, cross-model review.

## Rollout shape

Done when `pnpm --dir site test`, `lint`, `typecheck`, and `build` pass,
`pnpm --dir site build --base /beebox/` passes, root typecheck covers the
research scripts, a second `publish.ts` run changes nothing, and a take plays
in WebKit. No migration.
