# Plan review — place-shows-cards

Reviewer: codex gpt-6-sol, effort high, 2026-10-11. Round 1 findings verbatim below, then the planner's adjudication.

## Ranked findings

The boxholder authorized all three experiences: an agent-written landmark body, an “Also here” fallback, and summary lines. The smallest sound version keeps those three and cuts or corrects the extra machinery below.

1. **The agent has no reliable trigger to maintain the body.** Track C says the agent updates it whenever it changes what a place holds ([plan §Right place, right time](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:86>), [§Track C](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:346>)). But the always-loaded guide tells agents to read landmark instructions *before editing a landmark*, not when saving an ordinary card ([guide.md](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/agent-guide/guide.md:393>)); the type doc is on demand ([guidance-surfaces.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/box/guidance-surfaces.ts:107>)). An agent can save a loan without encountering the update rule. A journey already records the analogous missed root-landmark opener edit ([C report](<~/src/beebox-worktrees/place-shows-cards/beebox/test/user-stories/journeys/C-reconnecting/reports/2026-10-09.md:139>)). **Smallest remedy:** put the card-change trigger in always-loaded guidance and test a turn that edits an ordinary card without first opening its landmark. A knowledge quiz about the landmark type alone does not test this path.

2. **The proposed stale sentence cannot truthfully be computed from mtimes.** Track C calls the landmark file’s mtime `bodyWrittenMs` ([plan §Track C](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:365>)). Concrete state: write the body Monday; change a loan Tuesday; edit only `navigation.openers` Wednesday. The landmark mtime is now Wednesday, so `changedSince` becomes zero although the body predates the loan. Checkout or sync can likewise reset file mtimes without changing when the prose was written. **Smallest remedy:** omit the stale sentence from this version. If the product requires a dependable freshness claim, recording a body revision or write time is **human decision required** because it adds durable state.

3. **The tile-summary path would silently lose summaries as specified.** Track B says `cardIdentity` will call `cardParts` on cached frontmatter ([plan §Track B](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:304>)). `cardParts` is private and validates its fields against a schema requiring `type` ([loader-registry.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/loader-registry.ts:76>), [cards/schema.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/cards/schema.ts:553>)). The cached reader returns raw YAML ([card-io.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/card-io.ts:258>)); normal loading injects `type` separately ([card-io.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/card-io.ts:123>)). A valid `loan` without an on-disk `type:` would therefore fall back to its base summary, leaving `detail` absent while only logging a warning. **Smallest remedy:** use the exported `summarize` path with validated fields, injecting the filename type as normal loading does; test a valid box-authored card with no on-disk `type:`.

4. **“Nothing here yet” will still assert false emptiness.** Track A says the copy appears only when the place holds no cards ([plan §When it goes wrong](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:110>), [§Track A](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:277>)). The walk skips a card with an unregistered type and stops at nested landmarks; background cards are deliberately excluded ([prominence-index.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/landmark/prominence-index.ts:200>), [prominence-index.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/landmark/prominence-index.ts:236>)). A folder holding only its briefing still gets the current “Nothing here yet” copy ([PlaceView/view.tsx](<~/src/beebox-worktrees/place-shows-cards/beebox/src/frontend/src/components/PlaceView/view.tsx:55>)). **Smallest remedy:** say “No cards to show here yet” when the visible sections are empty; do not claim the folder is empty.

5. **The Browse count changes meaning at nested landmarks.** Track A promises a recursive count including nested places, derived from the pruned walk ([plan §Track A](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:281>)). That walk stops when it finds a child landmark ([prominence-index.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/landmark/prominence-index.ts:200>)); today’s count walks recursively ([status.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/webapp/trpc/routers/status.ts:106>)). A parent containing only a nested place with five cards would show zero under the proposed calculation. **Smallest remedy:** leave the Browse count change outside these three experiences, or specify and implement a separate recursive count with an accurate label.

6. **Background-defaulting `briefing` hides a person-readable card in Browse.** The plan calls briefings agent guidance and accepts Browse folding as a cost ([plan §Track A](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:261>), [§Stated preferences](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:167>)). Its schema explicitly says the person reads the briefing as their own page ([briefing.tsx](<~/src/beebox-worktrees/place-shows-cards/beebox/src/schemas/briefing.tsx:63>)). With a primary sibling, Browse moves a background briefing into the dimmed “more” tier ([browse-fold.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/shared/browse-fold.ts:135>)). Recent chats use their own session enumeration, while search eligibility is separate from prominence; neither offsets this Browse change. **Smallest remedy:** decide explicitly whether briefing should become background globally or be excluded only from the fallback. That visibility choice is **human decision required**.

7. **“Newest first” is an unstable promise.** Track A orders the fallback by filesystem mtime ([plan §Track A](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:266>)). The existing expand sorter uses mtime for “modified” order ([resolve/core.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/landmark/resolve/core.ts:265>)), but it does not establish a durable card-edit chronology. After checkout or sync, unchanged cards can acquire new mtimes, changing which ten appear. **Smallest remedy:** describe and test this as local “recently modified” ordering with a deterministic path tie-break, or use a durable ordering source. Durable chronology is **human decision required** if “newest” must survive sync.

8. **The embed direction risks printing the title twice.** Track B asks `MarkdownCardView` to render title, detail, body, then fields ([plan §Track B](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:321>)). Embed mode already puts the common `title` field in the front field block ([card-field-faces.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/frontend/src/lib/card-field-faces.ts:30>)). Moving that block after the body without removing `title` yields a second title there. **Smallest remedy:** take `title` out of the embed field block when rendering its dedicated heading; test the full rendered order.

9. **Two failure-mode claims overstate existing safeguards.** Landmark cards have `searchable: false` ([landmark.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/schemas/landmark.ts:176>)); search refresh drops non-searchable types before the `contains` sidecar observes them ([search/refresh/core.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/search/refresh/core.ts:147>)). Thus the plan’s one-time landmark `contains:` staleness and wakeup backfill are not established ([plan §Failure modes](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:409>)). Separately, validation does inspect body links, but a broken ref is a **warning**, not a guarantee that the landing page remains correct ([card-lint/core/lint-cards.ts](<~/src/beebox-worktrees/place-shows-cards/beebox/src/core/card-lint/core/lint-cards.ts:181>), [plan §Agent-flow edge cases](<~/src/beebox-worktrees/place-shows-cards/beebox/docs/plans/place-shows-cards.md:425>)). **Smallest remedy:** remove the `contains` transition and describe broken-link validation as warning-only.

**Single most important change:** make landmark-body maintenance reachable from an ordinary card-writing turn, then verify that actual agent flow. Otherwise the authorized main experience can remain empty while all schema and rendering tests pass.
