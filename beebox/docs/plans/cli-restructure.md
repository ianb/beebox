# `bbx` CLI Restructure — Plan

Proposed reorganization of the `bbx` CLI surface. **Not yet implemented** beyond a few resolved items below — this doc records the plan so it persists across sessions and we can implement in focused passes.

Drafted: 2026-05-01.

**2026-07 update:** the capture-processing commands this plan discusses renaming/grouping (`bbx transcribe-captures`, `bbx describe-images`, `bbx assemble-timeline`) were deleted outright, not renamed — the old `process-captures` pipeline retired in favor of the preparation-worker + chat-agent-annotation flow (`docs/implemented-plans/capture-mode.md`). Mentions of those three below describe the pre-retirement CLI surface; treat them as historical, not a pending rename.

## Why

Audit found 40+ registered top-level commands with inconsistent grouping: noun-only (`bbx activity`, `bbx drive`), verb-only (`bbx finish`, `bbx finalize`), hyphenated noun-verbs (`bbx assemble-timeline`, `bbx describe-images`), and confusable pairs (`bbx finish` vs `bbx finalize`). A few commands are dead. The agent's daily surface is hard to discover and the dev/admin surface is mixed in with it.

The goal is a CLI where:
- Frequently-used agent commands stay top-level and short.
- Resource-management commands cluster under their resource (`bbx connector ...`, `bbx schedule ...`).
- Naming follows one consistent shape per group.
- Confusable pairs get renamed.
- Dead commands are deleted, not left in the help output.

## Already done

- **`bbx context` removed.** CLI command deleted; `generateContext()` moved to `src/webapp/context.ts` (only the webapp tRPC router and HTTP API route used it). Removed from `src/core/agent-guide/commands.ts` and from `generateCbCommands()` in `src/core/docs-gen/index.ts`.
- **`bbx format` removed.** Manual normalizer with zero callers. Future card-normalization work tracked separately (see Side issues below).
- **`bbx init-rules` standalone removed.** File moved from `src/cli/commands/init-rules.ts` to `src/core/init-rules.ts` (library only). Imports updated in `src/cli/commands/init.ts` and `src/dev/prompt-report.ts`. Prose in `prompt-report.ts` changed from "generated by `bbx init-rules`" to "generated when `bbx init` runs"; `docs/prompts.md` regenerated. The `generateRules()` function still runs as part of `bbx init`.

## `bbx connector` group

Singular noun, parallel with `bbx job` / `bbx schedule`. Optional `[name]` scopes to one; default is all.

| New | Was | What it does |
|-----|-----|--------------|
| `bbx connector list` | (new) | List configured connectors with status |
| `bbx connector sync [name]` | (was `bbx wakeup --connector X`) | Pull inbound for a connector ad-hoc |
| `bbx connector flush [name]` | `bbx finalize` | Send outbound (Telegram messages, push notifications) |

`bbx wakeup` still does its full multi-phase cycle; `bbx connector sync` is the cleaner ad-hoc form when you just want to pull from one source without the wakeup machinery.

## `bbx import` group (file → box)

> **Namespace note (2026-05-20):** This group was originally proposed as `bbx intake`, but the bare `bbx intake` is now occupied by the triage-pipeline stage-1 command (`docs/triage.md`). Renaming the file-import group to `bbx import` resolves the collision and matches the verb better — these commands *import* external files into the box; they don't run the pipeline's intake stage.

*File ingestion* only — file → box, agent-runnable. Processing-of-already-imported items (transcribe, describe) stays top-level.

| New | Was | What it does |
|-----|-----|--------------|
| `bbx import scan <pdf>` | `bbx scan-import` | Import a scanned PDF / image batch |
| `bbx import upload <files>` | `bbx upload` | Batch-upload files (dedup by hash) |

If `bbx image describe` / `bbx audio transcribe` ever feels right, revisit. With only one command each (`describe-images`, `transcribe-captures`), grouping is over-organization.

## `bbx procedure` group

Already exists (`bbx procedure run`, `bbx procedure list`). Keep as is.

Procedure-internal commands that are invoked from procedure cards (rather than directly by humans) stay flat — promoting them into the group adds typing for no readability win.

## `bbx chat` group

Already exists (`bbx chat self-note`). Keep as is.

## New since this plan was drafted

- **`bbx refresh-maps`** (commit `5def6f1`) — new command added independently
  during this review. Not yet audited. When applying the remaining renames,
  classify it: agent-facing? procedure-internal? Does it want a group home?
- **`bbx hub`, `bbx upgrade`, `bbx boxes`** — added for the v2 (package-layout)
  box world: `bbx hub` supervises per-box child processes behind one router
  (see `docs/adding-a-box.md`), `bbx upgrade` is the per-box engine-upgrade
  lifecycle verb (bump dependency, migrate, sync templates, typecheck,
  commit), and `bbx boxes` manages the older manifest used by the pre-hub
  `bbx serve`/scheduler shape. None of this plan's renames or groupings
  anticipated these; audit them into the taxonomy when resuming this pass.

## Side issues surfaced during the audit

- **Card normalization story.** `bbx format` was deleted (80-line one-off normalizer that re-serialized cards to flat XML). We still want *some* way to keep cards normalized — open question on the right shape: a pre-commit hook that auto-formats on stage? A library function called by `bbx create` / `bbx mv` so cards are always written normalized in the first place? A periodic `npm run`-style sweep added to `docs/maintenance.md`? Decide before this becomes a noticeable drift problem.

## Open questions / not-yet-decided

- Should `bbx describe-images` and `bbx transcribe-captures` get a `bbx image` / `bbx audio` home eventually? Defer until a third command lands in either category.
- Should procedure-internal helpers ever fold into `bbx procedure run <name> --step <id>`? Probably not — current shape is fine for the ones that exist.
- Should `bbx connector sync` replace some uses of `bbx wakeup --connector X`? Both exist for now; `--connector` filter on wakeup might be retired later.

## Migration plan

The renames are independent — implement in any order. For each rename:

1. **Update the command registration** in `src/cli/commands/index.ts` and `src/cli/index.ts`.
2. **Implement the new shape** (e.g., add a parent command with subcommands; old command becomes a subcommand).
3. **Search and replace** call sites in: agent prompt builders (`src/core/agent-guide/`, `src/core/reactor/prompts.ts`), procedure templates (`templates/procedures/*.card`), generated docs (`generateCbCommands()` in `src/core/docs-gen/index.ts`), tests, scheduled-script cards in test boxes, READMEs.
4. **Regenerate** in-box agent guides via `bbx init` (or just `generateDocs()`).
5. **No deprecation aliases.** The boxes are personal; no third-party scripts depend on `bbx` command names. Just rename.

Suggested order — smallest blast radius first:

1. **Deletes** (`format` if confirmed; `init-rules` CLI requires touching `prompt-report.ts`). Fewest call sites.
2. **`bbx finish` → `bbx finish-job`** — agents reference this often, but the rename is mechanical.
3. **`bbx finalize` → `bbx connector flush`** + add `bbx connector list` and `bbx connector sync`.
4. **`bbx scheduled` / `bbx tick` / `bbx scheduler` → `bbx schedule ...`**.
5. **`bbx calendar` → `bbx calendar list ...`**.
6. **`bbx scan-import` / `bbx upload` → `bbx intake ...`**.

After each pass: regenerate `docs/generated/bbx-commands.md` in test1 and verify the agent-facing surface still tells a coherent story.

## Two parallel agent-command sources of truth

`src/core/agent-guide/commands.ts` (a 13-bullet list injected into agent context) and `generateCbCommands()` in `src/core/docs-gen/index.ts` (a fuller reference written to `docs/generated/bbx-commands.md` in each box) currently overlap inconsistently. Pick one as canonical and have the other reference it, or — better — auto-generate the table from Commander metadata and hand-write only the example sections. Worth doing as part of this restructure since every rename touches both files.

## Delete this doc when done

Once the migration is complete, delete this file (the review `CLAUDE-MD-REVIEW.md` that used to gate this has since been deleted). The state of the CLI is then the README + `docs/generated/bbx-commands.md` + `bbx --help`.
